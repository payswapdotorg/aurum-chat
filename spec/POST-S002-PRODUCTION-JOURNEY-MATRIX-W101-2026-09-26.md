## 1. Purpose

W101 is the final post-S002 release gate. It extends the W079
certification machinery with the post-S002 journey matrix (J16–J22) and
certifies the complete production journey set — cross-channel
communication, meetings, cellular reachability, integrations, provider
choice/billing, durable cognition and specialist execution — against the
current production deployment with the same discipline: real production
authentication, evidence generated by the same execution that produced
the verdict, and the two-run same-revision rule.

The W079 contract is FROZEN: its §5 matrix (J01–J15), its evidence root
(`docs/productization-evidence/W079/`) and its committed evidence remain
the historical record. W101 adds; it never rewrites.

## 2. The honest BLOCKED channel (extending W079 §2)

The W079 verdict vocabulary is unchanged: **CERTIFIED READY** only when
every mandatory gate is PASS; **BLOCKED** when any mandatory gate is
BLOCKED; **FAILED** when the deployed system violates a contract or
journey assertion.

W101 extends the vocabulary's MECHANICS with the journey-level blocked
channel, because the post-S002 matrix names journeys whose mandatory
surfaces may not exist in the deployed revision:

- A journey whose work-order-named surface does not exist in the deployed
  revision **stays BLOCKED** — never weakened to PASS, never substituted
  with preview evidence, never silently skipped.
- The journey's browser spec still runs and proves everything that IS
  provable through the real production surfaces (real auth, zero
  violations, transcripts, screenshots, per-test records), and records
  machine-checkable **blocked reasons** (the v1 public API's own
  discovery document, the navigation surfaces, the repo's closed route
  catalog) with probe evidence.
- The folding maps such a journey to status `blocked`; the run verdict and
  the final two-run verdict are BLOCKED. A FAILING assertion still
  dominates: a real defect is FAILED, never BLOCKED.
- Absence probes ride only legitimate production paths (the discovery
  document, the navigation hubs, the command search). No guessed-URL 404
  navigation pollutes the zero-violation record.

## 4. The program model

- **W079** (default, historical): mandatory set J01–J15; evidence root
  `docs/productization-evidence/W079/`; the W079 document names; the
  historical repository identity. The browser suite greps to the frozen
  fifteen journeys so a historical pass never folds post-S002 specs into
  its verdict.
- **W101**: mandatory set J01–J22; evidence root
  `docs/productization-evidence/W101/` (run directories
  `production-run-<a|b>/` under it, same wipe-before-pass law); document
  name `W101-PRODUCTION-JOURNEY-CERTIFICATION.md`; repository identity
  `work/w101-final-certification` @ base `a2db98a…`; and the
  rollback-evidence gate.

The finalizer refuses to pair runs from different programs into one
two-run verdict.

## 5. The rollback-evidence gate (the acceptance's rollback dimension)

Every W101 pass records, as the rollback evidence surface:

1. the deployment/health seam's recorded state a rollback preserves
   (environment label, database backend class, migration count);
2. the worker seam's recorded state (authorized observability snapshot:
   environment, queue depth);
3. the prior READY production deployment from the read-only Vercel
   listing — the known-good rollback target;
4. the committed rollback runbook (`docs/DEPLOYMENT.md §12`) and the
   linked (never restated — W079 §8) W078 operations evidence tree.

The S003-era user-visible rollback surface — the installed-extension
governance lifecycle (recorded transitions, deployment history &
rollback) — rides J22's browser journey where an installed extension
exists. A live rollback is NOT performed (the certified production
deployment is never modified).

## 6. Dimensions carried on the new journeys

- **Tenant isolation:** each new surface asserts its session envelope's
  tenant id and its tenant-scoped roster/state; the deep two-tenant proof
  remains J13's. Cross-tenant/unknown ids answer uniformly.
- **Approval authority:** /approvals renders the human gate (J19); the
  advanced preferences area honestly refuses non-administrators and the
  company preference form is administer-gated (J20); the marketplace
  review queue documents its claim gate (J22).
- **Accessibility:** every new user-facing page carries the shell
  accessibility probes (skip link, content landmark, keyboard walk with
  visible focus rings) via the shared W101 a11y layer; J15 remains the
  dedicated accessibility journey.

## 7. Reproduction

```bash
bun run cert:production -- --program w101 --target https://aurum-chat-livid.vercel.app \
  --run a --deployment-id <dpl> --expect-commit <sha> --deployment-created <iso> \
  --worker-token-file <path> --vercel-token-file <path>
# then --run b against the SAME deployment revision, then:
bun run cert:production -- --finalize --program w101
```

The verdict vocabulary and the two-run same-revision rule are the W079
contract's §2/§7 exactly. A BLOCKED verdict with complete, honest
evidence naming the exact missing surfaces is a valid W101 delivery
state; it is never a release approval.
