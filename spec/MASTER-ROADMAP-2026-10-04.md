# Aurum Master Roadmap — 2026-10-04

This roadmap unifies the two previously approved but not yet run handoffs with the newly approved Agent Body, Provider Fabric, Contextual Lab, Agent Exchange, Execution Platform and Cross-Platform direction.

## Product objective

Aurum becomes the company's information and coordination employee whose model is replaceable, whose organization is learnable, whose information-acquisition strategy is learnable and whose specialist execution workforce is recruitable and governed.

## Work items

### W124 — Repository Truth Reconciliation
Reconcile actual main, active PRs, current-state files and the coverage frontier. Identify and retire duplicate handoff instructions.

### W125 — Company Coverage Registry and Measurement
Measure breadth, depth, freshness, identity continuity, provenance, temporal completeness, outcome completeness, permission completeness and goal sufficiency.

### W126 — Company Query Plane
Create one provider-independent company query surface over authorized evidence with provenance, freshness, contradictions, unknowns and material coverage gaps.

### W127 — Coverage-to-Goal Attention Loop
Turn material coverage gaps into attention, unknown and learning-mission candidates connected to goals.

### W128 — Closed-Loop Deviation Monitor
Compare observed company reality to desired goals and distinguish reality deviation from knowledge deviation.

### W129 — Business Interaction Coverage
Measure meeting, customer and ticket interaction coverage using existing adapters; never imply universal surveillance or guaranteed capture.

### W130 — Coverage Benchmark and Certification
Certify the coverage/query/closed-loop frontier with exact revision and deployment evidence.

### W131 — Execution Platform and Cross-Platform Architecture Study
Convert ZCode, OpenMuse, Meta Muse, Epoch and Flauz patterns into Aurum-owned execution-environment, task-worker, browser/computer, shared-client and cross-device contracts. Freeze adopted/rejected patterns and adapter boundaries.

### W132 — Provider Fabric and User-Selectable Models
Implement canonical ProviderDefinition, ProviderAccount, ModelCatalogEntry, ModelBinding, wire-protocol adapters, model discovery and health/availability states.
Acceptance includes known-provider connect, custom provider for an existing protocol, model discovery/manual fallback, model switching, single canonical registry, and two-provider swap evidence.

### W133 — Aurum Agent Body + Model Binding
Separate persistent Aurum body from selected model. Body identity, company state, evidence and learning survive model changes.

### W134 — Goal/Context-conditioned Information Strategy
Learn what must be known, preferred information sources, freshness/confidence targets, acquisition cost and escalation thresholds for a specific goal and context.

### W135 — Contextual Organizational Lab
Implement model-agnostic bodies, context fingerprints, candidate organizations, marketplace-agent selection, model occupancy, multi-seed evaluation, calibration and outcome learning.
Same task subject with changed season, duration, staffing, staff experience or constraints must be allowed to yield a different best organization when evidence supports it.

### W136 — Agent Exchange + Execution Plan + Cross-Agent Relay
Discover and recruit approved specialist AgentPackages; persist orchestration plans; route minimal context; relay progress/results/evidence; support dependencies, approval, cancellation and recovery.

### W137 — Execution Environment / Agent Computer Fabric
Provide interchangeable browser, workspace and sandbox adapters. Initial candidates: local/fixture environment, Playwright/Chromium, E2B or equivalent remote sandbox.

### W138 — Emergent Roles + Marketplace Publication
Generate evidence-backed role proposals when recurring capability gaps show that current roles are insufficient. Role publication remains marketplace-governed.

### W139 — Cross-Platform Product
Web canonical, Desktop Tauri 2, Mobile Expo/React Native, all sharing semantic/client contracts and cross-device continuity.

### W140 — Unified Closed-Loop Learning
Connect Company Coverage, Goal Deviation, Information Strategy, Organizational Lab, Agent outcomes and CompanyModel learning.

### W141 — End-to-End + Cross-Platform Certification
Prove model swapping, company query, context-sensitive Lab selection, marketplace recruitment, cross-agent relay, execution environment, outcome calibration and cross-platform continuity.

## Mandatory product journeys

Ride: user -> Aurum -> ride agent -> ride provider -> PaySwap agent -> payment -> Aurum.

Construction: goal -> context fingerprint -> Lab organization -> recruitment -> people/system/site information relay -> execution agents -> evidence -> deviation detection -> Aurum.

Provider: connect provider -> discover models -> select model -> use Aurum -> swap model/provider -> continue same body.

Context: same construction subject with different season/duration/staffing/experience -> Lab may choose different organization.

Cross-platform: open work on web -> continue on desktop -> inspect/capture on mobile -> authoritative state remains identical.

## Completion law

Code, contract, tests, architecture gate, integration evidence, exact commit and live/fixture classification are all required.

Fixture evidence never proves live provider/runtime performance.

The Lab may recommend; only the existing authority systems may authorize and execute.
