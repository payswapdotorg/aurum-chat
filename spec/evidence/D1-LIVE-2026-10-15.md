## 4. The pure-router ruling (the dispatch-transaction starvation)

The draft transport resolved the tenant's ACTIVE cognition binding **inside** `transport.send` — and the agents service invokes `send` **inside its open dispatch transaction**, whose own code documents the law: *"a base-connection read inside an open transaction would starve the embedded database's single connection."* On the embedded PGlite (single connection) this deadlocked exactly as the law predicts: the dispatch transaction awaited the transport while the transport awaited the connection the transaction held (live-caught: the vitest worker burning CPU with zero network sockets and no output past the RUN banner; isolated by a standalone bun probe — the identical journey green in 6.6s outside vitest — and a logging-decorator bisect that hung precisely inside `send`).

**The fix is architectural, not a workaround:** `buildLiveAgentRouter` — the composition boundary (the executor, between submit and pump) resolves the ACTIVE binding through the fabric contract **on the base connection, outside every dispatch** via `refreshRoute(ctx)` and hands `{endpoint, modelId}` to the transport; `send()` is a **pure router** over the cached route and never queries the DB. This is the duty split the service's own law implies: whoever executes resolves the binding and routes; the transport only speaks the provider wire protocol (chat/completions, adapted into the openai-assistants dialect at the transport edge — the sanctioned seam).
